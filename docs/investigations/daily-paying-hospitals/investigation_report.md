# 每日氪金医院清单调查与实现报告

## 目标

在运营总览增加最近 7 日每日氪金医院清单，按日期、医院、渠道和金额展示明细，并提供每日汇总与 7 日统计总览。

## 已验证事实

1. 运营总览从 `/api/stats` 加载完整数据，页面入口为 `app/templates/dashboard.html`，服务端入口为 `app/app.py` 的 `load_stats_from_prod`。
2. Stripe、Paddle、Steam 订单实体均包含 `hospital_id`，可关联 `t_hospitals.id` 取得医院名称。
3. 现有充值统计把订单金额视为最小货币单位，并统一除以 100 展示。
4. 完成口径沿用现有统计：Stripe、Paddle 为 `status='COMPLETED'`；Steam 还要求 `delivered is true`。

## 实现口径

- 时间范围：看板时区内今天及前 6 天，共 7 个自然日。
- 明细粒度：日期、医院、渠道、币种。
- 金额：同粒度订单金额合计，最小货币单位除以 100。
- 每日汇总：按日期和币种汇总金额、医院数和订单数。
- 7 日总览：按币种展示总金额，同时展示去重付费医院数和订单数。
- 展示顺序：左侧日期倒序；右侧选中日期的明细按最近支付时间倒序。
- 页面交互：每日汇总和医院明细放入固定高度滚动区域，明细表头固定。
- 联动交互：左右滚动区域保持同高，默认选中最新日期；点击或使用键盘选择左侧日期后，右侧只显示该日明细。
- 明细顺序：每个日期、医院、渠道、币种聚合行返回最近支付时间，右侧按该时间倒序展示。

## 风险与限制

- 本机未配置生产数据库连接，因此本次没有执行生产 SQL。支付字段证据来自同工作区后端实体定义，SQL 通过单元测试和页面契约测试验证。
- 金额按既有 `/100` 规则处理。若未来接入零小数币种，需要引入按币种确定小数位的换算规则。

## 验收结论

- 单元测试通过。
- 桌面端页面没有横向溢出，明细区域存在真实纵向滚动，控制台没有警告或错误。
- 移动端断点、截图和最终版本提交结果见 `test_results.md` 与 `FINAL_RECEIPT.md`。
